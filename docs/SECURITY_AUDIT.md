# Speak FM security audit

Reviewed 2026-09-29 as a baseline before the static adverts/reviews/contact-form conversion. This is a read-only audit; no fixes were applied in that phase. Current implementation status is documented in `docs/CLOUDFLARE_DEPLOYMENT.md`.

## Dependency result

`npm audit --json` completed with exit code 1: 31 vulnerabilities total — 13 high, 17 moderate, 1 low, 0 critical — across 944 installed packages (`package.json:10-34`, `package-lock.json`). The report is dominated by the Vue CLI 5 / webpack development toolchain, including `yorkie`, `postcss`, `serialize-javascript`, `webpack-dev-server`, `browserslist`, `svgo`, `nanoid`, and `cross-spawn`. Several fixes require a major-version change or have no automatic fix. Do not run `npm audit fix --force`; plan a separately approved toolchain upgrade. The direct dependency declarations are also old or pre-release-oriented: Vuetify is declared `^3.0.0-beta.0` and ESLint is `^7.32.0` (`package.json:16,28`).

## Findings

| ID | Severity | File and line | Finding, impact, and concrete fix |
| --- | --- | --- | --- |
| SEC-001 | High | `src/components/NewsArticles.vue:25-27` | WordPress title and excerpt are rendered with `v-html` without visible sanitization. Third-party HTML can become stored/reflected XSS in the station site. Request plain-text fields or decode/render text; if HTML is unavoidable, sanitize with a narrowly configured, approved sanitizer and test it. |
| SEC-002 | High | `src/components/NewsArticles.vue:19-23,30-34` | Featured-media URLs and article URLs are accepted from remote content or assembled from an external slug. Unsafe URL schemes, changed URL structure, or hostile API data can create phishing/navigation risk; remote images also leak visitor IP/referrer data. Request only expected fields, require `https:`, validate hostname against an allowlist, and link to the API-provided canonical URL. |
| SEC-003 | High | `src/components/HomeHero.vue:17-19`; `src/components/radioSchedule/LiveShowSlide.vue:29-36` | The stream URL is hardcoded twice and has no explicit error, reconnect, or mixed-content guard. A changed or HTTP stream can fail silently or be blocked by browsers. Centralize an HTTPS-only configured URL and expose a graceful unavailable state. |
| SEC-004 | High | `src/views/HomeView.vue:1-10` and project inventory | Reviews are absent, so the required backend validation, pending moderation, email privacy, rate limiting, honeypot/timing checks, and CORS restriction do not exist. Before implementation, choose hosting and moderation; then enforce the two-endpoint-only contract server-side and never return email. |
| SEC-005 | Medium | `src/components/NewsArticles.vue:51-68` | The WordPress request has no timeout, cache, `_fields` restriction, CORS fallback, or friendly external-news fallback. A slow/changed third-party server can delay or degrade the page and may broaden the data rendered. Use an abort timeout, short cache, minimal fields, plain text, and a resilient fallback link. |
| SEC-006 | Medium | `public/index.html:1-15`; no deployment config found | No CSP, HSTS/HTTPS policy, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, or frame protection is defined. Missing response headers weaken browser isolation and clickjacking/mixed-content defenses. Configure them at the chosen host; use a restrictive CSP with only the required origins. |
| SEC-007 | Medium | `src/plugins/webfontloader.js:7-19`; `src/plugins/vuetify.js:1-8` | Runtime Google font loading and the full MDI font add third-party requests and supply-chain/privacy exposure. Self-host the one or two approved font families, limit weights, and use a minimal icon strategy; add SRI for any unavoidable static third-party asset. |
| SEC-008 | Medium | `src/components/ContactUs.vue:16-43`; reviews absent | Public contact email is displayed, but there is no documented privacy notice, consent, or retention policy for the future review email field. | SEC-009 | Low | `dist/js/*.js.map` generated by the build; `src/components/NewsArticles.vue:63` | Production source maps are present and the client logs fetch errors. Disable public production source maps unless protected upload is used, and use a controlled client-safe error path. |
| SEC-010 | Low | `public/index.html:7-8`; `src/components/ContactUs.vue:46-80` | The HTML shell has only a favicon/title and the footer shows placeholder social icons without destinations. Missing metadata does not directly create an exploit, but weakens trust and may lead to unsafe future link additions. Add verified `theme-color`/OG metadata and real, validated HTTPS destinations only. |

## Third-party content and advert plan

The safest advert implementation is station-controlled static data and images rendered as text/image links, with a fixed-height labeled “Advert” slot. Do not add third-party ad scripts, arbitrary HTML, iframes, autoplay media, pop-ups, or overlays without a separate security review. If an external ad provider is later required, isolate it behind an allowlisted sandbox/CSP policy and require SRI where technically applicable.

## Privacy and review requirements

The future review form collects name, email, feedback, and rating. Collect only what moderation/contact requires, show a concise purpose/retention notice, keep email server-side, set length limits, and store submissions as pending. The public response must contain at most the five newest approved reviews and no email fields. Use a honeypot, minimum completion time, per-IP rate limit, and only add a privacy-friendly CAPTCHA if those controls prove insufficient.

## Prioritized top five fixes

1. Remove unsanitized WordPress `v-html`; render plain text and validate external URLs (SEC-001/002).
2. Centralize and validate the HTTPS stream/WordPress configuration and add timeout/fallback/cache behavior (SEC-003/005).
3. Choose review hosting/moderation and implement the minimal server contract with server-side validation, pending approval, private emails, CORS, and rate limiting (SEC-004/008).
4. Add host-level security headers and remove public production source maps (SEC-006/009).
5. Reduce third-party font/icon exposure and schedule an approved dependency/toolchain upgrade instead of force-fixing (SEC-007 and dependency result).
